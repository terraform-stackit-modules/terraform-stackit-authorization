# Terraform STACKIT Authorization module

Terraform module which manages [STACKIT authorization](https://registry.terraform.io/providers/stackitcloud/stackit/latest/docs/resources/authorization_project_role_assignment) custom roles and role assignments (organization, folder, project and service-account levels) on [STACKIT](https://www.stackit.de/en/).

## Usage

```hcl
module "authorization" {
  source  = "terraform-stackit-modules/authorization/stackit"
  version = ">= 1.0.0"

  project_custom_roles = {
    deployer = {
      resource_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
      name        = "example.custom.deployer"
      description = "Custom deployer role"
      permissions = ["iam.subject.get"]
    }
  }

  project_role_assignments = {
    reader = {
      resource_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
      role        = "reader"
      subject     = "app-service-account@sa.stackit.cloud"
    }
  }
}
```

**Permissions needed by the caller** (a service account running Terraform):
- role assignments → the **IAM Member Admin** role on the target project (`iam.member.add`);
- custom roles → the **`iam.role.add`** permission — a HIGH-PRIVILEGE permission (per the STACKIT
  docs it allows adding arbitrary permissions to the created role), usually carried by the project
  Owner/Editor roles. Not covered by IAM Member Admin.

## Composite module

- `modules/organization` — `stackit_authorization_organization_custom_role` + `stackit_authorization_organization_role_assignment`.
- `modules/folder` — `stackit_authorization_folder_custom_role` + `stackit_authorization_folder_role_assignment`.
- `modules/project` — `stackit_authorization_project_custom_role` + `stackit_authorization_project_role_assignment`.
- `modules/service-account` — `stackit_authorization_service_account_role_assignment` (Act-As permissions).

Each level is a map keyed by a **stable identifier**; every entry carries its own
`resource_id`, so a single root module can manage roles across several projects/folders.

## Notes

- The STACKIT **IAM authorization API is experimental** and may undergo significant
  changes (see the provider docs) — expect possible breaking changes upstream.
- **Role assignments require the provider experiment**: add `experiments = ["iam"]` to your
  provider block. Custom roles work without the flag; role assignments fail at plan time
  without it ("part of the experimental feature iam, which is currently disabled by default").
  The `basic` example sets it.
- Role assignments: `role` names are relative (e.g. `reader`); available roles can be
  queried via `stackit curl https://authorization.api.stackit.cloud/v2/{resourceType}/{resourceId}/roles`.
- `subject` must be lowercased (user email, service account email, or client name).
- Service-account level assignments grant **Act-As** permissions: `resource_id` is the
  **target service account ID** and `subject` the service account allowed to impersonate it.
- The resources are **region-agnostic** — this module has no `region` variable and no
  `project_id` variable (resource IDs are passed per entry).

## Examples

- [`basic`](./examples/basic) — minimal role assignment, self-contained (requires only `project_id`
  and the IAM Member Admin role for the caller).
- [`custom-roles`](./examples/custom-roles) — project custom role + assignment; requires the
  high-privilege `iam.role.add` permission for the caller.
